# 图片素材接入与画面升级计划（v0.3）

日期：2026-10-27。基于用户提供的 60 张独立透明 PNG，以及当前 `car-playroom` 0.2.0 代码。本文是下一轮实施方案；当前网站尚未按此方案替换素材。

执行进度：第一步和样板场景已在本地完成。快递站欢迎、关卡、选车、订单、货架和配送舞台已使用源 PNG，首页快递入口改成同一素材风格；CSS 构成天空地面与连续道路，60 张裁切图按需加载。剩余旧小游戏的逐款适配及线上发布待完成。

## 目标与边界

把“汽车快递站”做成首个画面完整、可重复玩的样板：车辆、货物、地点、树木和路边物件都从这套统一素材中组合；同一批元素在欢迎页、选车、订单、游戏场景和结束页保持一致。完成样板后再推广到大厅和其他游戏。保留现有玩法、语音、音效、暂停、记录和登录方式。

**最终画面以原始透明 PNG 为准。** 本批素材为 320×220 画布、总计约 2.37 MiB。自动描摹得到的 `svg/` 和 `svg-smooth/` 可继续用于比较，但边缘和内部细节与原图有可见差异，暂不作为上线素材。需要无限放大的按钮图标、文字和道路连接线，继续用原生 SVG/CSS 绘制。这样整个场景仍是可组合的独立素材，而非一张固定背景图。

## 实施顺序

### 1. 建立运行时素材库与尺寸规范

保留 `assets/illustrations/individual/png/` 原图不动；制作可发布的 `public/assets/illustrations/v1/`，按透明像素范围去除多余留白，并记录每张图的可见边界、宽高比、地面锚点和语义 ID。界面通过单一资源表按 ID 引用，不在组件里散写 `01_...png` 路径。导出脚本需可重复执行，并校验 60 个源文件、透明度及映射是否齐全。

目标显示范围：游戏舞台车辆约 160–260 CSS 像素宽，货物按钮图约 60–100 像素宽；最终值在 iPad 横竖屏下以清晰度和触控间距实测调整。运行时可优先保留原 PNG；是否改用 WebP/AVIF，以实际画质与传输体积比较决定。若在高像素密度 iPad 上放大后确实发糊，再向素材源头要更高分辨率版本，单纯放大现有文件不会补回细节。素材文件用版本化路径，避免发布后旧图缓存。

### 2. 做一个可复用的“仓库出发送货”样板场景

先只做一个完整可交互画面：天空/远山 → 草地/道路 → 仓库/树木 → 货架/包裹 → 快递车 → 前景路边物。场景以相对坐标和锚点配置，不把位置写死在 1024×768 截图上。统一车辆轮胎接地线、仓库门前停靠点、包裹起点/落点、目的地停靠点；前景物件不能挡住可点击的货物或按钮。装货与行驶仍用现有状态机驱动，只替换视觉层。先生成横竖屏对照图，定下层级、尺寸与留白，再批量替换。

建议组件边界：`Illustration` 负责按资源 ID 显示和无障碍文字；`DeliveryScene` 负责地点与分层；`SceneConfig` 定义背景、路边物和锚点；游戏状态机继续决定“装货、出发、到站、卸货”。装饰图 `pointer-events: none`，互动由大按钮负责。

### 3. 完成快递站的全部画面

把 `games/delivery/art.tsx` 中的货物、站点和整幅 `World` 绘制，逐步替换成素材组件与三种可组合场景；在 `games/delivery/scene.tsx` 的欢迎、关卡、选车、订单、货架、示范、暂停/完成画面使用同一套图片；调整 `games/delivery/delivery.css` 的分层、响应式尺寸和动画路径。先保持现有 12 辆车供选择；额外 6 辆只放进资源表，待玩法适配后再开放，避免选车页一次出现 18 辆。

货物进入车厢和卸到地面复用同一源图；记忆阶段仍按原规则遮住会泄露答案的货物。整车 PNG 无独立车轮层，行驶改为轻微整体位移/起伏和环境滚动；如果以后需要车轮旋转，再补分层车轮素材，而不是从描摹图里硬切。`prefers-reduced-motion` 继续提供静态替代。

### 4. 统一大厅，再逐款改旧游戏

大厅精选卡片、类别卡片和游戏列表优先换成同一批素材。其余小游戏按实际机制处理：找不同、数独、听指挥、修车、修桥等可复用固定外观车辆；**汽车分类的颜色规则依赖运行时换色**，不能把固定配色 PNG 直接替进去。该玩法保留现有可变色 SVG，或在补齐同车型多色素材后再整体迁移。红绿灯/排队/改道的路面先复用场景系统，再逐个检查遮挡与提示表达。

此阶段不靠“全部换图”作为完成标准。每款游戏分别核对图片是否清楚表达题意；不能让漂亮装饰干扰孩子找目标、记顺序或理解轮流。

## 验收标准

1. 欢迎、选车、订单、货架、配送舞台、示范和完成页的同一车辆/货物外观一致；没有旧画风物件混杂、文字烙在插画内、透明边缘黑白毛边或图片拉伸变形。
2. 仓库、消防站、工地三场景在 iPad 横屏 1024×768 与竖屏 768×1024 浏览器尺寸下，都能看清车、道路、目标地点和主要按钮；点击热区不被装饰图盖住。浏览器模拟与真实 iPad 核对分开记录。
3. 8 个快递关卡的装货、记忆遮挡、路线选择、送达、重复点击、错误提示、暂停恢复与结束仍正确；全站已有游戏规则和语音/音效不因换图失效，尤其检查按颜色分类。
4. 记录冷缓存首入和暖缓存再入的图片请求量、总传输体积与解码时间；大厅不预载 60 张图，进快递站先载当前画面，后续关卡按需预取。加载失败时明确重试入口，游戏仍可用图文提示继续。
5. 本地确认后再同步 GitHub 和同一个 Sites 项目，保持 `/game` 和 `/game/delivery` 入口与当前访问控制。上线后在实际 iPad 上复核清晰度、声音、横竖屏与主屏幕入口。

**第一轮最小可检查成果**：资源表和导出脚本、仓库场景样板、快递车/包裹/仓库/道路/树木的实际拼接、两种 iPad 尺寸截图。样板通过视觉和操作检查后，按第 3、4 步扩展，而不是先批量替换所有页面。
