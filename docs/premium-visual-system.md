# 汽车小镇：4–6 岁界面与素材规范

2026-10-30，本地验收版本。设计对象是清楚、可反复玩的汽车任务，不对儿童能力作评价。

## 共用界面

`components/game-header.tsx` 统一十款的返回、声音、家长、休息；快递额外保留声音设置。标题28px，控制64×64px，返回按已有页面层级执行。

`app/game-design.css` 定义米白 #faf8ef、卡片 #fffdf5、深绿 #294b4a、辅助文字 #526f5c、绿色 #5c8b72、金色 #d4a84f。任务标题28–36px，主要按钮22px、关键标签20px、必要辅助文字至少18px。按钮至少56×56px，常用头部控制64px。选中同时使用边框和底色；错误反馈说明可调整的位置，不扣分。

页面保留各自场景，不统一成同一种表单。数独棋盘、找不同两边比较区始终稳定；分类完成展示整理后的分区；维修、过桥、巡游和地图保留实际行动的终点。

所有游戏图片阻止长按菜单和拖出，游戏区文字不选中；家长面板恢复正常文本选择。只监听游戏插画的 contextmenu/dragstart，不禁用浏览器缩放，不添加全站 touchmove 拦截。真实 iPad 手势仍需设备验证。

## 同一车辆的三种用途

| 用途 | 母版与实现 | 必须保持 |
|---|---|---|
| 普通场景、棋盘、首页、选择 | `illustrationUrl` 原 PNG；`vehicle-frames.ts` 管理透明范围 | 同一 ID、颜色、比例、轮胎、装备 |
| 修车故障/零件/成果 | `repair-master.ts` 坐标裁片；SVG 只遮罩、裁切、移动原 PNG | 正确零件来自同一车，不重新画一个轮胎或车身 |
| 分类换色 | `vehicle-art.tsx` 对原公交车/货车的车身区域着色 | 车窗、灯、轮胎、轮廓保留，类别色与规则一致 |
| 地图转弯 | `overhead-v4` 对应12辆车的俯视图 | 颜色、车窗、车轴和关键装备对应；0度朝右 |

维修六车型分别定义车窗、轮胎或履带轮、车灯或机身盖板、梯子/后门/护板/货箱门/挖斗/吊钩。擦布只擦污渍；扳手装轮或紧固装备；螺丝刀紧固灯或盖板。当前动作约950ms，可以暂停、退出。完成试车3秒，同一母版驶到右侧展示位，轮胎用原图裁片转动。

## 反馈节奏与成果

- 排队：车位与车票从左到右为1→N，车头与出口朝左；落位220ms，正确队列保留；下方按1→N依次向左出发。
- 修桥：实际放置的板构成连续桥面，轮胎落在桥面上，过桥2.8秒。
- 分类：归位约550ms；最后一次转移结束后展示整理好的分区。
- 路口：车辆和行人各约1.2秒通过。双向侧视车只走水平车道，反向车头向左。
- 听指挥：3.2秒依次停靠本局的2–4站，逐站标记到达。
- 改道：3.2秒走实际路径；俯视图按相邻格方向转向，解开角度避免整圈旋转。
- 找不同：对应位置同时确认，完成柔和描边并列出本局差异车辆；不移动原比较区。
- 数独：180ms落位、600ms行列反馈、约3秒停车庆典；最后一格不叠播普通答对语音。
- 快递：保留装货、行驶、货物送入站点和回库成果；记忆关卡盖住订单，可见订单关卡继续显示。

完成在逻辑成功时提交一次记录，动画结束不提交记录。返回、重开、换难度取消旧动作。系统减少动态效果时直接显示静态成果。暂停冻结过程；完成后切后台或打开家长面板结束装饰，回前台不重播庆祝。
