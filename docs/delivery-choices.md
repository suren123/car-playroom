# 快递站：可设置的备选货物与目的地

> 本文保留 v5 的设计与验收历史。当前 v6 的实际货物数、目的地数、竖屏固定画面和新验收结果见 [多站配送与竖屏升级](delivery-routes-portrait.md)。

本轮仅本地交付；不提交、推送或发布。沿用现有 50 种货物、20 个目的地及全部图片、拼接语音和完成效果。

## 家长设置

入口：任意快递站准备页或游戏中 → 顶部家长面板 → 设置。

| 设置 | 范围 | 不计入额外数量的内容 |
| --- | --- | --- |
| 额外货物 | 按任务 / 0–8 件 | 订单要求的 1 或 2 件货物 |
| 额外目的地 | 按任务 / 0–6 个 | 订单要求的 1 或 2 个站点 |

预设：轻松找 +1/+1，仔细找 +3/+2，小挑战 +5/+4。数字按钮逐一调整，不缩小候选图片来塞入更多选项。

“按任务”：货物沿用第 1、2、3、5、6、7 任务额外 1 件，第 4、8 任务额外 2 件；目的地第 1–4 任务额外 0 个，第 5–8 任务额外 1 个。

新设置按账户保存于 `car-playroom-delivery-choices-v1:<encoded account>`。不存在、损坏或越界时回到按任务；不改写旧任务、车辆、声音、历史及待同步记录。存储失败仍可在当前页面使用，并显示提示。

准备页修改在下一次出发生效。游戏中修改只影响下一整局（三份订单），当前局全部订单保持原配置；重开和再玩使用最新配置。刷新或重新进入仍回准备页，不恢复局面。

## 游戏规则

- 每单货架包含全部正确货物 + 指定额外数量，最多 10 件。对整个候选集合执行混淆过滤，包括干扰项之间。数量不足报错，不静默减少；有确定性回溯保障。
- 目的地包含全部真实站点 + 指定额外数量，最多 8 个。候选固定洗牌，不以顺序或货物标记提示答案。
- 已装货物留在原位并禁用。已到站点留在原位，显示“已送到”并禁用；提前选择第二站仍是答错，不扣分。
- 单站、额外目的地为 0：保留自动出发。单站、额外目的地大于 0：先在订单中展示并播报站点，然后进入选择。
- 两站任务始终先选第一站。第 7、8 任务先判断剩余货物，额外目的地大于 0 时再选择第二站；为 0 时保留自动前往第二站。
- 看单任务保持订单可见；记忆任务在记好后隐藏，仅重看订单时显示。剩余货物题保留已送货物作为候选，不标出剩余答案。
- 固定种子、任务、历史和设置可重现同题。干扰项随机流与订单独立，调整候选数量不会改变正确订单。

## 界面和资源

1024×768 横屏将订单放左侧，货物最多 5 列、目的地最多 4 列；768×1024 竖屏将订单放在候选区上方。选择阶段缩短背景场景，保留大图、名称及至少 56px 的点击区域。手机窄屏使用 3 列并允许纵向滚动。

复用现有预加载清单和名称语音片段，无新增 PNG/音频；静音预加载、取消、缓存与释放机制不变。两类候选在整个订单内固定，不在点击后移动。

## 记录与兼容

局次版本 `delivery-choices-v5`；元数据包含原任务模式、正确数量、配置版本 1、请求配置、实际额外数量和总候选数。seed、levelId 使用原字段。

近期出题信息使用冻结的 v1 货物/站点编码表压缩，仅用于种子重现，不是可恢复局面。元数据保持在原接口的 500 字符限制内。编码表不得随素材排序变化，新增格式需要新版本。旧记录解释不变，新记录详情显示实际额外货物和目的地数量。

准备和加载阶段不创建局次；完成、网站返回和重开沿用一次性记录。原生后退、刷新、关闭不补交未完成局。API、数据库、旧历史、离线重试及清空机制不改动。

## 验收

- `npm run test:delivery-choices`：8 任务 × 10 个货物设置 × 8 个目的地设置 × 200 种子，共 128,000 局、384,000 订单。检查数量、唯一性、正确覆盖、全候选混淆排除、位置固定、非法/重复输入、路线顺序、剩余题、完整完成及设置隔离。
- 同一测试覆盖配置快照不可被外部修改、v1 历史编码往返、记录重现与 500 字符限制。
- `npm run test:rules`、`test:records`、`test:rounds`、`test:navigation`、`test:resources`、`check:assets`、`npx tsc --noEmit`、`npm run build`。
- 浏览器完整流程：`scripts/delivery-choices-qa.js`；边界流程：`scripts/delivery-choices-lifecycle-qa.js`。测试记录接口使用 mock，不写入实际家长历史；图片音频在准备完成后拦截，验证无临时请求。
- 截图与运行日志位于忽略的 `output/playwright/delivery-choices-*` 和 `output/delivery-choices-*.log`。
- 真实 iPad：未实测；桌面浏览器尺寸验收不代表 iPad Safari 真机声音和触摸已验证。

2026-11-01 最终结果：规则矩阵和以上全部检查通过。桌面 Chromium 在 1024×768、768×1024 各完成 8 个任务，共 16 局、48 份订单，132 次选择布局检查；16 条完成记录 ID 唯一，准备后媒体请求 0，页面异常 0。最终记录压缩接入后另完成 768×1024 第 8 任务最高配置一局，完成记录一次、媒体请求 0。

边界测试通过：自动/零值、单站自动行驶、两站剩余题自动行驶、局中改设置不影响当前及第二份订单、提示与重看、重开应用新配置、暂停返回、刷新不补交、准备页不记局、偏好刷新保留、离线记录按原 ID 重试及清空。该测试产生 4 个逻辑记录、5 次请求（包含一次预期的离线重试），最大元数据 255 字符，媒体请求和页面异常均为 0。

家长设置遮挡修正已截图复核。生产构建首次在 Windows 受限进程退出时出现 libuv 断言；使用完整本机环境重跑及最终构建均退出 0，未修改构建器来掩盖错误。
